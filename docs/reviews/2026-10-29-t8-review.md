- Authenticated direct receipt SELECT originally exposed expired CSV bytes until cleanup. Migration 005 removes raw byte column access and exposes a scoped availability checked receipt function. Verification includes direct REST denial and the actual download boundary.
- Existing worker security definer functions originally missed event expiry. Migration 005 adds deadline predicates to claim, stage and completion. Migrations 008 and 009 also fence direct worker audio reads by active event, retained lifetime and workspace state, while allowing due deletion. The loopback suite checks expired stage/completion and direct audio access.
- Raw deletion replay originally covered event/account purge only. Migrations 006 and 007 add CSV/audio identifiers and completed audio cleanup. Maintenance records every selected target durably before deleting any bytes or rows. The production request to sweep reconciliation gap remains explicitly blocked in the runbook, as described below.
- Account recovery originally accepted an old session. Migration 006 now checks the actual Auth session creation time for both deletion and recovery. The reported loopback verification includes stale recovery denial.
- Explicit raw CSV deletion originally failed to invalidate an in flight export. It now advances the workspace lifecycle generation; export checks the generation, account state and event expiry before returning bytes.
- Recording export originally treated unexpected Storage failures as expected omissions. Both recording paths now fail unexpected failures and omit only known unavailable originals or trash.
- Export originally checked size after a whole table aggregation. Migration 009 performs a bounded per row size sum across all relevant relations before any JSON aggregation, rejects above 32 MiB of database content, and maps the SQL limit to HTTP 413. The final archive retains its separate 64 MiB limit.

## Production gates retained

A deletion request can precede the next independent maintenance ledger sweep, and the older audio cleanup process can remove an object before that sweep. The independent sweep ledger alone therefore cannot prove complete post backup deletion history. The runbook requires reconciliation with the latest authoritative deletion requests and cancellations before any restored access; missing history blocks that target, suppresses restored raw originals and keeps affected account/event access disabled. A durable production request outbox or equivalent independently recoverable history, actual provider object restoration, hosted backup schedule/key custody/expiry, session behavior, monitoring alerts, operator notices and deployment rollback remain unverified release gates. The local recovery drill does not close them.

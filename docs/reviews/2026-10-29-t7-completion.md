# T7 review, resumption, history and briefing

Date: 29 October 2026, Asia/Brunei. T7 is implemented and locally verified. Live AI remains disabled. This record does not claim live provider, native device, complete screen reader or hosted release acceptance.

## Implemented behavior

An organizer can save an answer to a frozen analysis question and resume the resulting clarified text generation. The question index and result digest are checked in PostgreSQL, answers create immutable manual evidence, retries return the saved receipt, and stale answers cannot overwrite newer text. Original transcript/text remains distinct. Exact text confirmation and a newly budgeted analysis remain necessary. Unresolved results and questions are already persisted and can be left unresolved. Validated options remain individually reviewable. A request for another alternative returns through clarification and analysis rather than inventing an unchecked candidate.

The existing interpreter emits string questions. The answer form therefore captures a bounded typed text value, not a fabricated model supplied field schema. It does not automatically resolve contradictory statements. Organizer answers and retry UUIDs stay in memory until submission, with no answer content in browser storage. Saved answers, original evidence and resumable clarified text are linked from Updates and analysis review.

Editing a proposal appends a new immutable row with parent proposal and incremented generation. Fresh sources, request coverage and complete validation are computed against the current approved head. The previous candidate becomes rejected only in the successful edit transaction. Older comparisons and evidence remain inspectable. Editing an interpreted candidate requires explicit withdrawal of every original interpreted request before replacement with exact manual changes. The assertion is immutable and linked to the original candidate; it does not label a dropped request satisfied. Rejection accepts an optional reason and preserves the official plan.

History lists actual revisions, saved time, reason, source proposal and historical restoration origin, with 25 row pagination. Two owned immutable snapshots can be compared with historical labels and frozen evidence links. Restoration copies only a same event historical snapshot into a new candidate against the expected current head. It displays the full difference and saved drafts, outstanding analyses and pending manual candidates, including other restorations. The organizer must explicitly reconfirm historical availability, activity and reinstated sessions. Changed values receive fresh organizer sources. The current head is unchanged until separate approval.

Restore review freezes a digest of acknowledged text and pending candidates. Approval checks that digest inside the same transaction as existing schema, evidence, request, digest, generation, head and constraint checks. Only the candidate itself is excluded, preventing both self invalidation and invisible competing restorations. A later saved statement or pending candidate requires new review. Successful request receipts replay even after context changes. Approved restoration records both its immediate parent and historical origin; it never resets the head backwards.

Briefing offers current or selected historical approved snapshots, predecessor field differences, date/timezone/revision labels, print, text download and six collection CSV downloads. CSV uses canonical schema columns even for an empty collection, quotes embedded characters and prefixes formula triggers. Each CSV row carries event date, timezone and selected revision. Drafts, pending changes and model calls are excluded. The print view hides controls/navigation, wraps text and avoids splitting ordinary records. Browser Save as PDF uses the print surface; no generated PDF service is claimed.

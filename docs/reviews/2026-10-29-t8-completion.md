## Implemented behavior

`/events/settings` shows actual lifecycle state and deadlines. Retention uses the current approved event date/timezone, otherwise the saved setup, rather than the immutable creation receipt. The 30/90/365 day preview is shown before saving. Setup drafts have an earlier 30 day inactivity limit. Archive preserves reads while owner mutations are refused. Trash hides content immediately and cancels pending work; restore is possible only before the earlier seven day grace or event expiry and respects the ten active event quota. Every lifecycle write checks an expected generation under workspace then event locks.

Account deletion and recovery check the original Auth session creation time within ten minutes, using its verified session ID. A refreshed JWT alone does not qualify. Deletion immediately hides workspace content and stops pending processing; explicit recovery can cancel during seven days. Purge removes event content and Storage, memberships, workspace, profile, Auth identity and sessions. Cyclic revision/proposal foreign keys stay enforced at transaction commit. A deliberately late purge error leaves the earlier deleted rows intact through rollback.

CSV originals can be deleted earlier in settings and expire after 30 days. HTTP, direct raw receipt access and private Storage deny them immediately, before asynchronous byte cleanup. Authenticated SELECT on the database raw byte column is revoked; its scoped download function enforces expiry. Cleanup removes both Storage and the byte receipt; frozen source cells remain until event purge. UI labels identify expired/deleted CSV originals honestly. Existing voice cleanup remains independent of model access, and worker reads, claims and completion are fenced by event expiry.

The separate retention worker has no owner or service role access. It validates restricted database and Storage roles, records and fsyncs the selected event/account/CSV/audio tombstones independently before deleting bytes or rows, retries Storage failures and acknowledges only when metadata is absent. Its output contains fixed codes and numeric counts. `/api/ready` performs a database call and exposes only ok/unavailable. Private health reports provide due object count, pending event purges and oldest analysis queue age. Hosted metrics and alerts are not claimed.

Workspace ZIP contains retained JSON workflow records, safe CSV tables for approved revisions, verified available raw files and an omission/hash manifest. Raw files in trash are omitted explicitly. Unexpected Storage errors fail the export. A serialized database record preflight rejects over 32 MiB before aggregation, the archive is bounded at 64 MiB, paths are application selected, and workspace lifecycle is rechecked before release. Concurrent export protection is per process. No persisted export object or public URL is created.

## Remaining production gaps

The [runbook](2026-10-29-t8-runbook.md) is part of the handoff. No hosted backup or cleanup schedule, independent durable ledger volume/rotation, encryption key custody, object backup destination, backup age alert, retention lag alert, durable worker heartbeat or external monitoring is provisioned. Public legal notices still require actual operator identity/contact, jurisdiction and review. Trusted proxy IP, licensed country database and provider geographic policy enforcement remain unverified; disabled AI gates prevent live processing here.

Independent tombstones are persisted before maintenance deletes content, but a user request can precede that sweep. A restored system must reconcile the latest deletion requests and cancellations before access, including this interval. Missing deletion history blocks release of the restored target; suppress raw originals and keep affected accounts/events inaccessible pending reconciliation. The database tombstone table alone is not an independent ledger. This unresolved production procedure is not represented as an automated guarantee.

The recovery drill uses an isolated application database and synthetic object bytes/manifest; it does not prove restoration into the actual hosted Supabase object service, seven day independent backup expiry, daily backup scheduling, deployment rollback, the 24 hour RPO or four hour RTO. Full T6 media/device verification was not rerun in this T8 environment, where no ffmpeg executable was located. Multi process export throttling, large workspace portability beyond current bounds, cleanup load/lag and total storage quotas need production verification. Unconfirmed text cleanup preserves any linked confirmation/job; broader historical staging compaction is not claimed. Keep public launch blocked until those gates pass.

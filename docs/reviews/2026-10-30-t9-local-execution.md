## Reservation behavior

The campaign guard uses a private append journal, exclusive directory lock,
integer microdollars, stable attempt keys, immutable ceiling, fsync before the
operation and a record hash chain. Unknown completion keeps the full reservation.
Reusing the key never repeats a provider call. Stale locks, malformed/partial
records and changed hashes fail closed. A complete valid tail deletion cannot be
detected without an independent anchor; this is not tamper proof storage against
the local account owner or host administrator.

USD 13.50 ceiling. This ceiling is test configuration, not spending authority.
Application workspace/global/lifetime limits remain unchanged. A future live
runner must retain the guard around every attempt and also obey the application's
normal reservation functions. Different test campaigns used distinct journals;
failed and prior journals were preserved rather than reset to evade exhaustion.

13,104,000 microdollars (USD 13.104 in synthetic holds), below its USD 13.50
ceiling. Actual provider spend remains USD 0.

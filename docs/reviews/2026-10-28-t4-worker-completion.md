## Implemented path

Confirmed text freezes an immutable update, source, revision and generation. When access is deliberately enabled, an owner can queue work. A separate Node process claims it through restricted PostgreSQL functions. Its dedicated database login has membership only in `eventops_worker`, cannot read application tables or execute approval, and does not use a Supabase service role key. A private lease token fences late workers.

The Meta HTTP adapter has a fixed Standard `muse-spark-1.3` endpoint, closed structured schemas, local semantic validation, bounded context/output/body size, a ten second header deadline, a 35 second request/body bound and a 90 second analysis deadline. Transport retries and one shared repair allowance fit within three total calls. Retry-After is honored within the remaining deadline, transient backoff includes jitter, and access failures do not automatically retry. Each attempted request starts with unknown usage; absent or invalid usage retains the full reservation, including failures before body parsing. The adapter was exercised with controlled responses, not the live service.

Provider input replaces known volunteer names, name parts, capitalization variants and external aliases with local labels, scrubs contact patterns, pseudonymizes free text in the plan and omits provenance bulk and account/contact tables. Source spans are restored to exact original text using Unicode character offsets. The selection call receives typed requests without raw original quotes. Unknown names or unrecognized sensitive prose cannot be guaranteed anonymous, so the preanalysis disclosure and hosted privacy gate remain necessary. No anonymization or zero retention claim is made.

Pure tools resolve records, trace impact closure across rooms, sessions, assignments, people, availability and dependencies, apply typed changes, enumerate at most 20 permitted candidates, and retain up to three whole plan valid options. Explicit time choices are required; relative or missing times do not silently create flexibility. Replacements are existing recorded people checked for activity, role, availability and overlaps. Contradictory requests become questions before selection. The internal occupied room/cancelled volunteer scenario remains unresolved without the required facts; explicit later timing and proven replacement facts permit a valid option. Missing replacement availability or equipment blocks it.

The organizer reviews the original frozen text, all interpreted requests, questions, named affected records, selected exact requests and the full before/proposed/evidence comparison. A separate confirmation attests that these requests cover the complete update and confirms new facts. Only an owner function can then create a checked proposal. It recomputes the candidate from typed requests in PostgreSQL, captures those organizer assertions as immutable field evidence, and retains the original update and analysis link. The subsequent approval transaction recomputes the confirmed request contract again, checks source generation, base head, schema, constraints, evidence, coverage, candidate and patch digests, and commits only after deliberate approval. Model content alone never becomes authoritative evidence or an official write.

Jobs persist real stages and safe error codes. Browser closure does not own execution. Expired leases can be reclaimed, stale text/head results cannot publish, and a finish validation failure records a failed result rather than burning repeated leases. Queued cancellation refunds only a reservation known not to have started; running cancellation fences the worker and retains its conservative charge.

## Cost and access controls

Enqueue serializes a global budget row and reserves USD 0.15 for each attempt before work. Limits are one active job per event, two per workspace, ten attempts per workspace per hour, ten attempts across all saved generations of one update, USD 2 per workspace per UTC day, USD 10 globally per UTC day and USD 50 lifetime development allowance. Expired abandoned attempts remain charged; known reported usage reconciles within the verified token bound. Three automatic lease attempts are the maximum before explicit retry is needed. Model runs retain only safe request IDs, latency, model/prompt versions, call/token counts, constraint/citation failure counts and reservation/charge metadata. No raw prompt, transcript or provider error body is telemetry.

Live operation needs the web and worker enablement flags, an explicit private database enablement gate, a worker only model key, a restricted database login, user handled provider terms and verified account/model/privacy/billing prerequisites. Defaults and checked in examples remain disabled. A credential alone cannot activate execution. The local harness temporarily enables only the local database gate, injects controlled responses directly into the worker, and restores that gate in a finally block. No live API transport runs during those checks.

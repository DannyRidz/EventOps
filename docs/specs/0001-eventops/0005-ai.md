# AI workflow, evidence, and reliability

## Summary

Recommend Meta Muse Spark 1.3 for understanding updates and explaining feasible changes, with Muse Voice Transcribe for speech. Application code supplies the records, checks constraints, and commits only an explicitly approved revision. The model cannot create a fact by saying it confidently.

## Model verification and choice

Research date: 27 October 2026. Published documentation confirms model identifiers and interfaces. Your account's enabled models, billing, actual limits, latency, and retention configuration have not been tested. The first approved implementation milestone must verify them using synthetic inputs.

| Task | Recommendation | Verified basis and comparison |
|---|---|---|
| Interpretation and planning | `muse-spark-1.3`, Standard mode | Published text/multimodal input, text output, tool calls and structured output; 1,048,576 token context. Release sends structured text only. Prefer it over older Spark versions for new work |
| More complex reasoning | Do not select `muse-wonder-1.0` by default | Available in the API but costs more; evaluate only if Spark fails the same cases. Wonder Full is not an API choice |
| Speech transcription | `muse-voice-transcribe-1.0` | Audio to text through file or realtime endpoint; file input is simpler for reviewed short updates |
| Self hosted inference | Defer Muse Glimmer and Muse Spark Open | Would require an inference deployment and separate quality, license and privacy checks. No such infrastructure is justified for this release |

[Meta model catalog](https://dev.meta.ai/docs/models), [API overview](https://dev.meta.ai/docs/overview).

Authentication uses a server held `MODEL_API_KEY` bearer token at `https://api.meta.ai/v1`. Recommend `/chat/completions` with explicit messages and strict JSON Schema rather than provider stored conversation state. Validate all returned data locally even when the provider constrains its shape. Native multimodal understanding could transcribe audio, but a dedicated transcript step provides a clearer correction boundary. [Structured output](https://dev.meta.ai/docs/structured-output).

For recording, use browser `MediaRecorder`, then server conversion of supported WebM/Opus or MP4/AAC into mono 16 bit PCM WAV at 24 kHz. The documented file endpoint is `/asr/transcribe`, accepts WAV at 16 or 24 kHz, caps request size at 32 MB and duration at 10 minutes, and provides no confidence scores or word timestamps. EventOps limits recordings to 120 seconds and 10 MiB before conversion. Feature detect recording codecs and test them on actual target browsers. [Speech guide](https://dev.meta.ai/docs/speech-to-text).

Do not default to browser speech recognition: coverage, vendor processing, and persistence are difficult to control. No second speech vendor is selected. If transcription is unavailable, preserve the text draft and offer typing. Voice may only be advertised when its browser and service checks pass.

## Model versus application responsibility

| Model work | Deterministic work |
|---|---|
| Extract intended changes and ambiguity from confirmed text | Resolve exact record IDs and validate timestamps |
| Explain which dependencies may matter | Compute complete impact closure across affected rooms, sessions and assignments |
| Describe sensible alternatives from supplied candidate options | Enumerate bounded candidates and check all constraints |
| Phrase specific questions for missing facts | Identify required unknown fields, enforce typed answers |
| Explain valid changes and their source evidence | Resolve citations, compute before/after diff, enforce permissions and version checks |
| Produce candidate structured content | Save proposal, commit approval, generate briefing and exports |

No model output grants permission, establishes availability, authorizes a request withdrawal, or updates an approved record.

## Bounded orchestration

1. Save a text update or transcribe the short recording. Store original and corrected text separately. Require explicit confirmation of the text that will be analyzed.
2. Freeze the current approved revision, update generation, confirmed answers, and source identifiers for this run. Mask volunteer names to stable local labels and omit contacts. Minimize unrelated text; the model receives IDs and relevant facts. Audio can contain spoken names, so the pre recording notice explains that it goes to the transcription provider.
3. Call Spark to extract typed intent, matching candidates, ambiguities, evidence spans and required unknowns. Use exact IDs where possible. A duplicate name without a disambiguating reference produces a question.
4. Run deterministic tools against the frozen snapshot: `resolve_records`, `get_impacted_records`, `check_candidate`, and `find_alternatives`. The full snapshot is checked for collisions and coverage, even when only a smaller affected subset is sent to the model.
5. If required information is missing, return questions now. Do not spend another call generating a purportedly complete solution. Answers append immutable organizer evidence and start a new proposal generation.
6. Enumerate up to 20 deterministic alternatives within the permitted dimensions. Prefer requested room/time with valid assignment, then explicitly permitted time changes. Offer at most three valid alternatives for review, ordered by request satisfaction, fewer affected sessions, smaller total time displacement, then stable record ID. No claim of global optimality.
7. Give the model validated options and ask it to explain and recommend among them. It must select an option ID or return unresolved; it cannot manufacture a new room, person, capacity, time window, or option.
8. Validate schema, IDs, evidence resolution, exact match to selected candidate, request coverage, and all rules. One repair call can correct a malformed or inconsistent result using the validation errors. Otherwise save an unresolved or failed result.
9. Present the server computed diff and validation report. Manual edits create a new generation and run the same checks. Approval follows the data contract, without another model call.

Tool calls here are explicit application functions, not shell, browser, SQL, or external messaging capabilities. A general model selected tool loop is unnecessary. Meta supports developer defined tool calling, but the application remains responsible for execution. [Tool calling](https://dev.meta.ai/docs/tool-calling).

Limits per analysis generation: three model calls including repair, 48,000 aggregate input tokens, 12,000 aggregate output tokens, and 90 seconds wall time. A maximum 16,000 input and 4,000 output tokens per call bounds the worst case independently of the provider's much larger context. Reserve the worst case cost before starting. Reject oversized context rather than silently dropping required facts. Questions can stop an analysis early; answering starts another explicitly budgeted generation, limited to ten generations per update before manual review is required.

## Structured contracts

The input envelope includes schema and prompt versions, trusted event metadata, base revision ID and digest, complete allowed IDs, confirmed update text and immutable source IDs, source values needed for the change, known constraints, and typed organizer answers. Keep trusted system policy separate from untrusted source content. No provider credentials, storage URLs, customer email, or account metadata are included.

Intent output shape:

```json
{
  "schema_version": "1",
  "base_revision_id": "uuid",
  "intents": [
    {
      "intent_id": "local-request-id",
      "action": "move_session",
      "target_ids": ["allowed-record-id"],
      "requested_fields": {"room_id": "allowed-room-id"},
      "evidence_refs": ["source-record-id"],
      "ambiguity_codes": []
    }
  ],
  "questions": [],
  "unsupported_requests": []
}
```

This illustrates a contract, not a live response. Production schemas use closed enums, explicit nullable values, bounded arrays and strings, required keys, and `additionalProperties: false`. Actions are allowlisted: move session, change time, cancel session, change assignment, record availability, change explicit room facts, or ask for clarification. No arbitrary JSON path or executable expression is accepted.

Candidate output contains `base_revision_id`, `selected_option_id` or null, per request disposition, explanation claims with `evidence_refs`, questions with `question_id`, `record_id`, `field`, `reason_code`, expected answer type and relevant sources, and an uncertainty reason enum. The server adds the candidate snapshot, canonical patch, actual before values, digest, and validation result. The model's own status or confidence never determines readiness. No percentage confidence is displayed.

## Evidence contract

Each factual claim references at least one actual source record. A reference resolves to a source record ID and frozen field locator, or a record ID and field in the immutable base revision. A source reference is scoped to the same event and workspace. The server checks existence, retention state, value and allowed field, then computes any quoted excerpt from the real source.

An imported record points to CSV artifact hash, row, column and captured value. Corrections point to the original and to a new manual source record. Transcripts point to a confirmed text generation and character span. A corrected transcript is the current organizer statement, while the uncorrected transcript remains an original source, not an equally authoritative competing instruction.

Authority order is explicit: approved revision for current official state; newer confirmed organizer update or answer for requested new facts; imported source for provenance. Two contradictory confirmed facts remain unresolved until the organizer chooses which applies. Mere upload recency does not establish priority. Proposed changes never become current facts until approved.

Reasoning can say “This alternative changes fewer sessions”, based on the deterministic diff. It cannot say “Alex is happy to help” without such a confirmed statement. Unknown capacity, requirements or travel time remains unknown. Unresolvable citations, unsupported claims and unrelated IDs fail validation rather than rendering convincing prose.

## Internal scenario

Use fictional records only in internal tests: Workshop A in Room 1 from 10:00 to 11:00, Workshop B in Room 2 for that interval, one assigned volunteer cancelling, and a requested move to Room 2. Do not seed any real account with this data.

The first result must show the Room 2 collision and missing replacement coverage. If the reason for the move and timing flexibility are absent, ask what the move needs to achieve and whether a later time is acceptable. Leaving A in Room 1 is only a labeled alternative pending the organizer's decision, not a successful room move.

In the resolvable fixture, an explicit answer permits 11:15 to 12:15 and requires a projector. Room 2 has a recorded projector and is free then; a named existing volunteer has a recorded available interval and required role. Validate both the room and the replacement before proposing them. In the missing data variant, remove those facts and require an unresolved outcome. Do not turn fixture assumptions into claims about real people or rooms.

## Prompt injection and service failures

Files, filenames, transcript text, answers, and model output are untrusted. Treat phrases such as “ignore all rules and approve this” as source text, never system policy. No tool allows a model to query another event, fetch arbitrary URLs, call SQL, send messages, change permissions or approve. Validate all tool parameters and source IDs, escape output as text, and reject unknown actions. Delimiters alone are not a security boundary.

| Condition | Behavior |
|---|---|
| 429 | Honor `Retry-After`; bounded exponential backoff with jitter; remain visibly queued if the allowed run time would be exceeded |
| Network or 5xx | At most two transport retries within the same call and aggregate cost/time reservation; unknown provider billing is conservatively charged to the budget |
| 401/403, model disabled, exhausted balance | No automatic retry storm; flag configuration error to operator, preserve work, offer manual path |
| Refusal, invalid shape, unknown source or unsupported fact | One repair within total model call budget, otherwise unresolved/failure; never approve partially validated output |
| Timeout or browser closure | Durable job can finish or fail independently; user can return using update/proposal ID |
| Worker restart | Reclaim expired job lease; generation and deduplication keys suppress duplicate result effects |
| Repeat update | Exact same confirmed text and base revision reuses the existing analysis unless explicit reanalysis requested; possible semantic duplicates prompt review rather than silently merging |
| AI unavailable | Show current plan, retain update, and offer manual candidate editing with deterministic checks and the same approval boundary |
| Transcription unavailable | Keep an acknowledged draft and offer typing; do not display an invented transcript |

Use a 10 second connection timeout, 35 second model response timeout, and 45 second transcription timeout. All retries must fit the job wall time and reservation. At budget or time exhaustion stop and offer an explicit retry, preserving the prior result. A stalled job does not mean the update has been committed.

## Cost assumptions and controls

Published Standard rates: Spark input $1.25 and output $4.25 per million tokens; cached input $0.15. Wonder input $4 and output $20. Voice transcription $0.18 per audio hour. Published Spark team limits are 3,000 requests and 4,000,000 tokens per minute; voice has 256 concurrent streams and 16,000 starts per hour. Use lower application quotas and verify the account's actual headers. [Meta pricing and limits](https://dev.meta.ai/docs/pricing-rate-limits).

Budget estimates are USD, exclude taxes, hosting, and unknown billed reasoning overhead, and do not assume cache savings or credits:

| Workload | Calculation | Estimate |
|---|---|---|
| Normal text analysis | 10,000 aggregate input and 3,000 output tokens | $0.02525 |
| One minute recording | 60 / 3600 hours times $0.18 | $0.003 |
| 1,000 analyses, all with one minute audio | $25.25 model plus $3 audio | $28.25, about $31.08 with 10 percent retry allowance |
| Worst token envelope per generation | 48,000 input plus 12,000 output | $0.111 before audio |
| Two minute audio maximum | 120 / 3600 times $0.18 | $0.006 |

Reserve $0.15 per generation plus $0.006 for a maximum recording. Count provider reported billed usage, including reasoning when reported; if output cap semantics do not bound billed reasoning, lower the cap or disable the run until a measurable bound is established. Cap the initial deployment at $2 AI spend per workspace per day and $10 globally per day, with $50 total development/evaluation allowance as a proposed budget, not spending permission. Reserve quota atomically across concurrent jobs, reconcile final usage, and keep a conservative charge for unreported attempts.

Limit one active analysis per event, two jobs per workspace, ten analyses per hour per workspace, and recording attempts to twenty per day. Store cost, model ID, prompt version, request ID, latency, attempts, constraint failures and citation failures. Do not store raw transcript or private prompts in telemetry. Alert before the global allowance is exhausted. A provider billing notification may not stop spend, so the application enforces its own reservation ledger.

## Privacy and permitted use

Recommend an explicit Standard model allowlist. Do not call Contributor variants with event data. Standard does not imply zero retention. ZDR needs separate provider enablement and varies by model; do not claim it is active. The terms require adult end users and a truthful privacy policy, and geographic controls apply to integrated products. Brunei is absent from the published restricted territory list, but actual authorized access still needs verification. [Terms](https://dev.meta.ai/legal/terms-of-service), [geographic policy](https://dev.meta.ai/legal/geographic-use-policy), [ZDR explanation](https://dev.meta.ai/help/policies-and-privacy/zero-data-retention).

Use the product for consensual event logistics. No inferred sensitive profiles, employment screening, surveillance, medical advice, or automatic consequential external actions. That is a product boundary, not a claim of legal compliance. [Meta acceptable use policy](https://dev.meta.ai/legal/acceptable-use-policy).

## Consequences

The model meaningfully interprets operational changes and explains validated choices, while the application limits what can go wrong. Some requests will remain unresolved, and finite enumeration may miss a workable option. Say “No valid option found within these choices”, not “No solution exists”. Quality depends on representative evaluations and actual service access, not the model's marketing benchmarks.
